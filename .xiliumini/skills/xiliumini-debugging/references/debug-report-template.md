# 调试报告模板（Debug Report Template）

这是 xiliumini-debugging 技能规定的固定调试报告模板。每次调试任务结束时都用本模板汇报，章节必须齐全、顺序不可变、标题不可改名（英文标题保持不变，便于机器解析）。正文用中文填写。

使用方式：复制下面的八个章节，逐项填空；没有内容的章节也要保留标题并写明“无”或“暂无证据”，不要删章节。

---

## Symptoms

用一句话描述可观察到的现象：错误信息或异常类型、失败的测试名、异常行为表现，并注明出现时间、频率与影响范围。

## Reproduction

写出最小复现步骤与可复制粘贴的命令/输入，标明复现率（如 10/10 或 1/20）、前置环境（依赖版本、配置、数据）以及本次是否成功复现。

## Evidence

列出支撑判断的原始证据：stack trace 关键帧、日志片段、`git log`/`git diff` 变更、对照实现的差异、实验或埋点输出；每条证据注明来源与采集方式。

## Root cause

用一句话给出根因，并指出是哪个边界或层级（进程/模块/序列化/网络/DB）引入了错误，说明支撑该结论的具体证据。

## Hypothesis

写出被验证的可证伪假设（形式为“如果 X 是根因，那么做 Y 会出现 Z”）、验证方式以及验证结果（证实/证伪）。

## Minimal fix

说明改动的文件与最小根因修复内容，解释为什么这样改只影响目标行为、不会波及无关路径，以及有无替代方案被否决及原因。

## Tests

列出建立失败测试（Red）、最小修复（Green）与回归测试所用的命令与结果摘要，注明修复前失败、修复后通过的对应关系。

## Remaining risks

说明剩余风险、未覆盖场景、可能的副作用以及建议的后续跟进项（含监控、告警或补充测试）。
